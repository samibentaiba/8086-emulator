# 8086 Circuit Workbench

The website explores 34 processor and system-board units. Its application,
demonstration model, schematic components, routing engine, and local preview
server are authored in TypeScript. The Python emulator remains a separate
application; the browser model illustrates ADD, SUB, and a memory-read sequence.

```sh
npm ci
npm run dev
```

Open the printed local URL. Use `PORT=8090 npm run dev` on Unix or
`$env:PORT=8090; npm run dev` in PowerShell to choose another port.

```sh
npm run typecheck
npm test
```

From the repository root, `python build_circuits.py` remains a compatible build
entry point, and `python tools/lint_schematics.py --all --strict` inspects all
rendered detail cards. The established Python launchers serve the built files.

## Source map

- `src/model.ts`: typed demonstration state, ALU, flags, and execution phases.
- `src/architecture.ts`: unit registry, named board ports, connection graph, and
  rendering at architecture and gate-detail scales.
- `src/app.ts`: camera, component navigation, keyboard, pointer, pinch, and
  viewport resize handling.
- `src/render-engine.ts`: viewport culling, bounded SVG cache, and retained DOM
  updates for visible scene objects.
- `src/engine.ts`: components, pins, schematic canvas, and route rendering.
- `src/routing.ts`: deterministic orthogonal routing around component bounds.
- `src/modules/`: existing detailed 8086 circuit definitions.
- `src/primitives.ts`: shared SVG shapes and escaped text.
- `src/server.ts`: dependency-free local HTTP preview server.
- `src/package-site.ts`: packages the public browser assets into `dist/`.
- `src/public-assets.ts`: shared allowlist for local preview and deployment.

Root-level JavaScript files and `tools/server.js` are generated by `npm run
build` and retained so the Python launchers can serve a fresh checkout. Edit
TypeScript sources, then rebuild. `npm run watch` watches schematic sources;
`npm run watch:ui` watches the browser application. Reload the browser after a
build.

## Static hosting

Run `npm run build:site` to compile TypeScript and create `dist/`. Deploy the
contents of that directory with `index.html` at the site root. It contains only
the seven browser assets and `.nojekyll`; source code, tests, dependencies, and
the preview server are excluded. Relative asset URLs support GitHub project
Pages under `/8086-emulator/` as well as a custom domain.

GitHub Actions builds and deploys this directory to GitHub Pages. No Python
process, Node server, database, or runtime secret is required by the hosted
workbench. The standalone Python emulator remains a separate application.

## Viewport rendering

The camera renders only cards, group frames, and wire paths intersecting the
viewport, with a 64-pixel preload margin to prevent popping during pans. This
applies at every zoom level. Wires are tested segment by segment, so a wire
crossing the screen remains visible even if both connected cards are off screen.
Off-screen cards never invoke their gate renderer and their SVG nodes are removed
from the document. The complete circuit graph remains available for navigation
and routing.

Visible SVG nodes are retained between camera frames. Only entering or changed
objects update their markup; a bounded LRU cache reuses generated SVG when moving
back to a previous region. Geometry, CPU state, selected component, bit, and level
of detail invalidate the appropriate content. Rendering pauses while the browser
tab is hidden. `board.render(...)` still supports a full SVG export without a
viewport. The `world` element exposes `data-render-*` counts for developer checks.

## Adding connections

Use `Component.addPin` with a local offset and outward direction. Pin positions
follow their component when it moves. Add components to `SchematicCanvas`, then
use `canvas.connect(source.pin("out"), target.pin("in0"))`. Connections resolve
after placement, with every component registered as an obstacle. Reserve text
and headers with `canvas.reserve({x, y, w, h})`; configure canvas bounds and
clearance in the constructor. The default clearance is six schematic units.

The board uses the same router and caches routes by component geometry. A
connection starts and ends at the same named ports used to render terminals.
An impossible route throws `RoutingError` instead of drawing through a gate.
Enlarge the layout or move components when there is insufficient space.

Tests exercise routing, moved components, blocked paths, pin directions, and
the production board. The inherited detail cards still contain fixed SVG
traces; the legacy SVG inspector is heuristic. Passing checks is regression
evidence, not a guarantee for every arbitrary arrangement of components.
